# Backend security findings

Audit date 2026-11-24. Scope includes the versioned API, legacy authentication, processor, PostgreSQL, Loki, Grafana and the checked-in Compose model. Verification used synthetic records and disposable loopback services. No CRITICAL finding was substantiated in the reviewed paths.

## HIGH

| ID | Status | Finding and evidence |
|---|---|---|
| SEC-01 | Fixed | The legacy administrator cookie contained an identity with no server-side revocation. Operational HTML and JSON now require a PostgreSQL session with a cookie-specific digest. Both logout routes delete that session and write the audit record in the same transaction. Bootstrap credential rotation invalidates old operational sessions, and a supplied Authorization header takes precedence on the JSON API. Existing operational browser sessions must sign in again. The native regression covers both logout paths, CSRF denial and an independent bearer session. [Session implementation](../app/web/accounts.py#L74) · [Cookie guard](../app/web/accounts.py#L243) · [Regression](../tests/integration/test_backend_operations.py) |
| SEC-02 | Open | Loki has no application authentication and stores normalized records containing raw text. Grafana provisions Loki into the same instance as KPI dashboards. A Grafana identity allowed to query Loki can see payloads independently of the NetworkSec role. Keep Loki on loopback/internal networking and restrict Grafana datasource access to authorized log operators. A view-only KPI SQL role does not protect Loki. Verify the real Grafana audience and endpoint before wider access. [Loki config](../infra/loki/loki.yaml#L1) · [Loki datasource](../infra/grafana/provisioning/datasources/loki.yaml#L3) |
| SEC-03 | Open | A fresh Compose deployment gives the application, processor and bot the PostgreSQL initialization identity. On a fresh cluster this identity is privileged and owns migrations and audit data. API roles cannot rewrite audit history through the API, but the database owner can. Use a separately reviewed runtime/migration role design and an external protected copy if audit history must survive database-owner compromise. Keep public rollout gated on privilege review. [Compose PostgreSQL configuration](../compose.yaml#L34) · [Audit schema](../migrations/postgresql/006_backend_operations.sql#L82) |

## MEDIUM

| ID | Status | Finding and evidence |
|---|---|---|
| SEC-04 | Fixed in API and HTML | The legacy JSON listing returned raw log text to cookie-authenticated administrators without an explicit detail request. Both auth transports now receive the same `[restricted]` field. Admin-only detail still requires `include_raw=true`. The legacy HTML evidence view masks recognized credentials. Native OSPF tests compare listing IDs with incident evidence, and the suppression logic preserves that identity. Redaction is pattern-based, so raw detail and Loki remain sensitive. [List serialization](../app/web/api.py#L158) · [Detail role check](../app/web/backend.py) · [HTML evidence](../app/web/routes.py) |
| SEC-05 | Fixed on reviewed API inputs | An uncapped alert page could exceed a valid SQL offset and text filters and incident notes could send NUL to PostgreSQL. Alert page limits and SQL-bound string validation now reject these inputs as 422. Extreme datetime conversions also return a client error. [Alert request guards](../app/web/api.py#L179) · [Note schema](../app/schemas/api.py#L104) · [Transport regression](../tests/test_storage_api.py) |
| SEC-06 | Open | The shared throttle bounds accepted attempts per process and source IP. It resets on restart and does not coordinate replicas. One worker is configured in the dashboard image. Before multi-worker or public use, verify trusted proxy handling and enforce rate limits at the edge. There is no claim of distributed throttling. [Throttle](../app/web/accounts.py#L46) · [Runtime command](../docker/Dockerfile) |
| SEC-07 | Open | The syslog listener has no source authentication. Matching an observed collector IP and vendor supports attribution, while UDP source confidence depends on the dedicated lab network and firewall. Keep the management path scoped to the confirmed routers and record the real source addresses. [Attribution](../app/storage/backend.py#L166) · [Published collector ports](../compose.yaml) |

## LOW and INFORMATIONAL

- **SEC-08 · LOW · OPEN.** The standalone SQLite demo still uses its signed, expiring administrator cookie. Logout clears that cookie in the browser. Use the operational PostgreSQL setup where server-side revocation is required. [Cookie guard](../app/web/accounts.py#L243)
- **SEC-09 · INFORMATIONAL.** New accounts use salted PBKDF2-HMAC-SHA256 with 600,000 iterations. Existing bootstrap hash formats remain readable. Opaque tokens are random, digested server-side, and checked for expiration. Role, password and enabled-state changes revoke managed-user sessions. Bootstrap credentials are managed through deployment configuration. [Password implementation](../app/web/auth.py#L12) · [Account mutation](../app/web/accounts.py)
- **SEC-10 · INFORMATIONAL.** All protected versioned operations returned 401 without authentication in the route-level regression. PostgreSQL tests cover role denial, account revocation, role updates, and literal searches. The lab assumes global roles over one inventory. No tenant or per-device ACL is implemented. [API authorization](../app/web/accounts.py) · [API coverage](../tests/test_backend_contract.py) · [SQL search regression](../tests/integration/test_postgres_ospf_lifecycle.py)
- **SEC-11 · INFORMATIONAL.** Explicit CORS origins and CSRF are exercised using allowed and denied requests. Request validation removes input and sensitive context from errors. Scenarios checked include secret redaction, formula neutralization in CSV, and transaction-linked audit entries with request IDs. The worktree ignores `.env`, and tracked filenames contained no populated `.env` or known capture/key extensions. The Python runtime and development requirements reported no known vulnerabilities through `pip-audit`. Container image scanning and a trusted-proxy review remain deployment checks. [Middleware](../app/main.py) · [Transport tests](../tests/test_backend_contract.py) · [CSV and audit tests](../tests/integration/test_backend_operations.py)
- **SEC-12 · INFORMATIONAL.** Rule definitions allow bounded typed fields, enums and sample counts. OSPF ownership and unsupported port-flap inputs are validated. SQL data values are bound and dynamic identifiers and clauses come from code constants or validated enum choices. Grafana parity tests exercise restricted views, while operational grants remain a VM setup task. [Rules](../app/services/managed_rules.py#L19) · [KPI permissions](grafana-integration.md)
